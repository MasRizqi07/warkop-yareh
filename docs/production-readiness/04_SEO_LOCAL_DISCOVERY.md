# Local discovery and indexability

The deployed baseline had duplicate or missing descriptions on seven secondary public routes, wrong canonicals including `http://localhost:3000/`, absent outlet-specific `CafeOrCoffeeShop` schema, indexable login/register and private routes, and sitemap/robots with the wrong origin. These are release defects until the new build is deployed.

The working build supplies unique page titles/descriptions and canonical paths for eight public marketing routes. Each outlet has branch-specific metadata and `CafeOrCoffeeShop` JSON-LD with verified name, address, postal code and branch URL; only Prapen has a telephone field. No rating, review count, coordinates, price range, reservation acceptance, or invented cuisine is emitted. The root `WebSite` schema uses the verified origin. JSON-LD escapes `<` before injection. The sitemap includes only the eight approved marketing paths, with no fabricated modification timestamps; robots points at the same verified origin. Auth, account, commerce, QR/table and admin routes use noindex; preview deployments send `X-Robots-Tag: noindex, nofollow`.

The browser sweep validates the rendered metadata, per-outlet schema, sitemap/robots, and 12 private URLs. It does not prove Google indexing, Search Console ownership, domain ownership, or that deployed environment variables match the local build. Configure `NEXT_PUBLIC_SITE_URL` to the verified domain and recheck rendered HTML, HTTP headers, sitemap, robots, crawler output, and a third-party structured-data validator after deployment. Map links in the smoke sweep must contain the correct address or Plus Code and use `noopener` when opening a new tab.
